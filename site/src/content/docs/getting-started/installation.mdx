HORUS runs natively on **Linux** (`x86_64` / `aarch64`), **Windows 10/11** (`x86_64`), and **macOS** on Python **3.10–3.13** (Python 3.12 recommended). A full install sets up **HORUS Studio**, the built-in 3D **Test world**, **Drone board**, and CPU vision runtime in one step.

## One-line installers

No pre-installed Python, `uv`, or `git` is required. Each installer bootstraps `uv` + standalone Python 3.12, installs HORUS, runs `horus setup`, and launches **HORUS Studio** automatically.

<Tabs syncKey="os">
  <TabItem label="Windows (PowerShell)">
    ```powershell
    irm https://horus-drone.github.io/horus/install.ps1 | iex
    ```
    Set `$env:HORUS_SKIP_SETUP = "1"` to skip asset downloads during install, or `$env:HORUS_NO_START = "1"` to install without auto-launching **HORUS Studio**.
  </TabItem>
  <TabItem label="Linux / macOS">
    ```sh
    curl -LsSf https://horus-drone.github.io/horus/install.sh | sh
    ```
    Set `HORUS_SKIP_SETUP=1` to skip downloading SITL/ONNX assets during install, or `HORUS_NO_START=1` to install without auto-launching **HORUS Studio**.
  </TabItem>
</Tabs>

After installation, launch **HORUS Studio** anytime with:

```sh
horus
```

## Where HORUS stores files

HORUS uses a hybrid storage layout based on how you run it:

| Mode | SITL & ONNX models | Session logs & runs | Settings, API secrets (`0600`) & TLS |
| --- | --- | --- | --- |
| **Source checkout** (editable `-e .` or running inside repo) | `<repo>/models/` | `<repo>/runs/` | OS user config dir |
| **Installed package** (`install.sh`, `install.ps1`, `uv tool`, `pip`) | OS user cache dir (`~/.cache/horus/assets`, `~/Library/Caches/horus/assets`, `%LOCALAPPDATA%\horus-drone\horus\Cache\assets`) | OS user data dir (`~/.local/share/horus/runs`, `~/Library/Application Support/horus/runs`, `%LOCALAPPDATA%\horus-drone\horus\runs`) | OS user config dir (`~/.config/horus`, `~/Library/Application Support/horus`, `%LOCALAPPDATA%\horus-drone\horus`) |

Override any location with `HORUS_ASSETS_DIR`, `HORUS_RUNS_DIR`, or `HORUS_CONFIG_DIR` (run `horus doctor` to inspect the resolved paths).

## Companion board install

On an onboard companion computer (e.g., BeagleY-AI / AM67A) that only runs the **Drone board** (`horus mcp`) without MuJoCo or cloud LLM SDKs, install the lean `board` extra:

```sh
pip install "horus-drone[board] @ git+https://github.com/horus-drone/horus.git"
```

Or from a local clone on the board:

```sh
pip install -e ".[board]"
```

## Optional extras

When installing into a specialized environment (a lean **AI pilot** host, a headless Gazebo container, or an open-vocabulary **Grounder** host), choose from the extras defined in `pyproject.toml`:

| Extra | What it installs | Typical use |
| --- | --- | --- |
| *(default)* | Studio, built-in 3D **Test world** (MuJoCo), **Drone board**, ONNX Runtime, OpenCV contrib, Anthropic & OpenAI SDKs | Standard laptop / workstation install |
| `board` | `PyYAML`, `mcp`, `uvicorn`, `pymavlink`, `numpy`, `onnxruntime`, `pyserial` | Companion computers running `horus mcp` only |
| `commander` | `mcp`, `httpx`, `uvicorn` | Lean host running **HORUS Studio** / `horus tui` against a remote **Drone board** |
| `server` | `commander` + `pymavlink` | Flight-only **Drone board** (`horus mcp --no-perception`) |
| `perception` | `numpy`, `onnxruntime` | CPU-only YOLOv8n + OSNet inference without Torch |
| `model-tools` | `onnx` | One-time ONNX batch-axis export (`scripts/fetch_models.sh`) |
| `opencv-headless` | `opencv-contrib-python-headless` | Local image/video CSRT tracking (no GStreamer) |
| `grounder` | `torch==2.5.1`, `torchvision`, `transformers`, `scipy`, `Pillow` | Optional `horus-grounder` open-vocabulary service |
| `test` | `pytest`, `commander`, `numpy` | Running the unit test suite |

:::caution[OpenCV in Gazebo containers]
Do **not** install `opencv-headless` inside the Gazebo simulation container. The pip `opencv-contrib-python-headless` wheel replaces Ubuntu's `python3-opencv` package and lacks GStreamer support needed for UDP H.264 video. Inside the sim container, use a virtualenv created with `--system-site-packages` and install `.[server,perception,model-tools,test]`.
:::

## Offline grounder cache

If `huggingface.co` is unreachable when installing the optional open-vocabulary **Grounder** (`horus-grounder`):

- Copy an existing Hugging Face `hub/` cache directory containing `models--IDEA-Research--grounding-dino-tiny` and/or `models--google--owlv2-base-patch16-ensemble` and set `HORUS_GROUNDER_HF_CACHE=/path/to/hf_cache` (enables `HF_HUB_OFFLINE=1`).
- Or pass `HF_ENDPOINT=<mirror-url>` to `scripts/setup_grounder.sh` using a mirror that serves full Hub metadata (`Content-Length` and `X-Repo-Commit`).

## Verify your environment

```sh
horus doctor
```

`horus doctor` checks the Python runtime, MuJoCo offscreen OpenGL, ArduCopter SITL binary, SHA-256-verified ONNX models (`yolov8n.onnx` and `osnet_x0_25_msmt17.onnx`), serial ports, Tailscale, and configured AI credentials.

## Updating & uninstalling

```sh
uv tool upgrade horus-drone
uv tool uninstall horus-drone
```
